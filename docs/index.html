01 From refusal removal to DWM

Abliteration research showed that refusal behavior can be traced to directions in activation space and suppressed with rank-one weight edits. DWM extends that foundation into a general, architecture-aware discipline: which writer, in which space, at which site, with what evidence.

The origin: abliteration

Contrast harmful vs. benign prompts, extract a refusal direction, project it out of a writer matrix: W′ = W − α·d(dᵀW). Effective — but fragile across architectures, and silent about what else changed.

The extension: DWM

Domain Weight Modification treats the edit as a declared experiment: explicit graph and writer identity, bounded plans, digest-bound artifacts, retained trial lineage, and hard gates that fail closed. The v0 runtime implements this discipline on synthetic tensors you can verify on a laptop — and, with the optional [real] extra, on small dense HuggingFace checkpoints you name by URL.

03 Every gate and its purpose

Eligibility is computed by evaluate_eligibility() in src/ablagent/policy.py. Gates are conjunctive: all must pass (with one narrowly-scoped exception for bank publication). Click any gate to expand its purpose.

Measurement layer: prompt-only benchmark corpora — a 443-row false-refusal eval (AdvBench / StrongREJECT / XSTest; MIT / MIT / CC BY 4.0), smoke-50, and cyber-10 — hash-pinned with an offline scorer, explicit states, and a rubric bound into every metrics receipt. S6/S7 remain skipped in real runs; no score grants eligible. An operator-controlled release-only corpus is intentionally absent.

Fail-closed hard blocks

Some conditions raise PolicyBlocked before any decision exists — they are not gate FAILs, they abort evaluation: passing red-line observations without a complete mock attestation; an attestation bound to a different bank or artifact; red-line metrics that don't exactly match the selected-bank attestation; an attestation present without its complete metric set. Tampering is an exception, not a score.

05 Evidence states & the identity chain

Every required metric carries exactly one state. “Behavior failed” and “the gate could not evaluate behavior” are different facts, and the protocol keeps them different.

Nothing floats free: the digest chain

Each artifact binds the digests of its inputs. verify-evidence reloads the graph and tensors, independently recomputes the update and observation, validates the selected trial chain, and checks metric references — offline, no credentials. Hashes provide tamper evidence, not author authenticity; signed approvals and a protected release system are separate responsibilities.

06 A real run, end to end: Inkling-2-Mini

The repo vendors the exact duplication kit published with Blackfrost-AI/Inkling-2-Mini-Derisked — byte-identical at a pinned revision, with a per-file SHA-256 provenance manifest and an offline verifier.

A hard architecture

A loop transformer: 24 physical layers, layers 6–17 executed in 3 passes per token — 48 logical layer-visits. Naive abliteration assumptions break here; the kit shows physical-vs-logical targeting and per-pass direction capture.

The shipped edit

Per-pass consensus column orthogonalization of the attention-writer output space, physical layers 9–18, α = 2.5, loop structure intact. The edit receipt binds the published weight shard's SHA-256.

Honest about its own record

Six inaccuracies in the original runbook were verified against the shipped scripts, corrected on Hugging Face, and preserved as correction history. The scripts and receipt are the ground truth — not the narrative.

07 From BF16 to 2-bit IQ

Quantization is part of the intervention surface. Blackfrost research has investigated BF16, FP8/MXFP8, NVFP4, GGUF/Q8_0 and IQ2_XXS — with the operation and evidence class kept explicit.

Format-aware research is broader than the current CLI's dense CPU executor
PathResearch operationBoundary
BF16Capture and dense float editsDoes not transfer automatically to a quant
FP8 / MXFP8Scale reconstruction and requantization round-tripsNot a validated FP8 intervention
NVFP4BF16→NVFP4 PTQ deployment; codec research; serializationNot native NVFP4 editing or retained behavior
GGUF / IQ2_XXSIQ-surface editing, selective Q8 promotion, packing checks and servingRetention and behavior are checkpoint-specific
EXL3Not yet proven for DWM editingNeeds dedicated end-to-end qualification

These are format-specific historical research results, not universal support claims. The current CLI edits only its qualified small dense float safetensors envelope; FP8, NVFP4, GGUF and IQ direct codecs are not implemented. 08 Run it yourself

Python 3.11+. No GPU, no credentials. The synthetic slice is fully offline; the real executor downloads only the checkpoint you name.

Install
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
Run the synthetic vertical slice
.venv/bin/ablagent demo --run-dir .runs/reference
Verify independently
.venv/bin/ablagent verify .runs/reference/candidate.manifest.json
.venv/bin/ablagent verify-evidence .runs/reference/candidate.evidence.json
Check the gate — expected: blocked, exit 2 (fail-closed demo)
.venv/bin/ablagent gate .runs/reference/candidate.evidence.json \
  --bank examples/banks/synthetic-release-mock.bank.json
Verify the vendored worked example (offline)
python scripts/verify_example_provenance.py
Run it on a real checkpoint (CPU; small dense models)
.venv/bin/python -m pip install -e '.[real]'
.venv/bin/ablagent run --pack derisk --executor real \
  --model https://huggingface.co/HuggingFaceTB/SmolLM2-135M --alpha 1.0

The real executor pins the commit, captures refusal-contrast directions (correlational, never causal), compiles the same digest-bound rank-one edit, and exports an HF-loadable copy with exactly one tensor changed. Quant, serve, behavior/capability verify, red-lines, and delivery are recorded as skipped — untested; the run ends not_eligible. An experimental artifact, never a release.
